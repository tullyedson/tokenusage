AI Usage 0.3.0 · Routing requirements and integration contract

One local endpoint.
Your accounts, in your order.

The tray app accepts chat completion requests from applications on this PC. It tries the requested model against enabled accounts in the user's priority order. When no account can serve that model, it tries only the alternatives the user explicitly configured. Every new request starts at the top again, subject to known rate-limit cooldowns.

Paid fallback is disabled. The app must not turn an included subscription limit into a charge against an API wallet or purchased credits. A provider is offered for inference only when its adapter enforces local, free, or included-only requests.

Set it up

  1. In Settings, expand LLM and a provider. Save a server URL and optional key for local Ollama or vLLM. The server must already be running. OpenRouter needs a standard API key and the standard-key usage source.
  2. Use Add another account for separate connections. Give each a label. Credentials, website sessions, usage readings, and model mappings belong to that account.
  3. Save or connect the account, then choose List server models. Add the models you want. A client model name is the name your calling app uses; a server model ID is its exact upstream name. Give equivalent models on several accounts the same client name.
  4. Enable routing for those accounts and save. Open the Routing page. Reorder accounts, then add fallback rules if you want model substitutions.
  5. Generate a client key and copy it into your calling app before saving. Enable the router. Use the displayed base URL and your client key in the calling app. Saved keys cannot be displayed again; generate a replacement if needed.

Example behavior

Account A and account B both map writer to their own server model IDs. A local account maps small. The fallback rule is writer → small.

  1. A request for writer tries A, then B.
  2. If A's included window is exhausted, B is used while that window remains blocked.
  3. If neither can serve writer, small is tried on the local account.
  4. After A's reset or retry time, A is checked again on the next request. A reset timestamp permits a new check; it does not invent a fresh usage percentage.
  5. With no eligible account or mapped alternative, the router returns an error. It does not buy credits, redeem resets, upgrade plans, or choose an unconfigured model.

Calling API

Default base URL: http://127.0.0.1:43129/v1. Use Authorization: Bearer <client key>. GET /v1/models lists configured client model names and fallback entry points, not a guarantee of current availability. POST /v1/chat/completions accepts JSON.

{
  "model": "writer",
  "messages": [{ "role": "user", "content": "Explain this idea." }],
  "stream": true
}

Supported request fields: model, messages, stream, stream_options, temperature, top_p, max_tokens, max_completion_tokens, stop, seed, frequency_penalty, presence_penalty, response_format, tools, tool_choice, parallel_tool_calls, logprobs, top_logprobs, reasoning_effort, and n. Only function tools executed by the calling application are allowed. The selected upstream must support the supplied fields. Responses, embeddings, audio, images, model installation, and native agent execution are outside this API.

Success responses preserve upstream JSON or SSE. Headers x-ai-usage-account, x-ai-usage-model, x-ai-usage-upstream-model, and x-ai-usage-requested-model identify the selection without exposing account keys. The response's model field remains the upstream model ID.

Selection and lifecycle rules

  • Account order is global. Exact client-model matches take precedence over every substitution, even if an alternative's account has higher priority. Fallback traversal is breadth first, preserving each rule's order and visiting a model at most once. Cycles are rejected.
  • Requests serialize per account, including the response stream. A queued request rechecks cooldowns after acquiring that account. Up to eight requests may be active in the router.
  • Known quota exhaustion is supplied by inference adapters, with an account or model scope and a retry time. HTTP 429 is treated conservatively as account-wide. Expired cooldowns trigger provider checks on a new request. Cooldowns live in memory; restarting requires fresh checks.
  • Connection refusal, 401/403, 402, 404, 429 and 503 can move to another eligible route before response output. Other upstream errors and ambiguous failures after submission stop the request. Once streaming begins, it is never replayed elsewhere.
  • Account or routing saves cancel active inference, including streams whose clients stopped reading. Disabling an account prevents new requests on it. Disabling the router releases the listening port. Exiting the tray app ends the process and listener.
  • Requests and streams have bounded waits. Non-streaming replies are limited to 8 MiB; incoming requests to 1 MiB. Streaming uses a bounded channel and ends on timeout, disconnect, or cancellation. Prompts and responses are never logged or saved by this app.

Provider extension boundary

IUsageProvider::inference() optionally returns an IInferenceProvider. Its definition drives the generic account settings. Implement validate, models, and prepare. The latter checks model-specific included allowances and constructs a fixed safe upstream request. Return Unavailable with retry time and scope for exhausted windows; return an error if usage or no-paid enforcement cannot be established. Every applicable window must allow the request.

The engine owns ordering, mappings, concurrency, credential isolation, transport, streaming, cancellation, and local authentication. An adapter must not reuse a consumer usage reading to authorize unrelated billable API traffic. A subscription adapter needs a verified provider-enforced no-overage mechanism before registration. Extend supported protocols through this boundary, with fixture HTTP tests, without provider-ID branches in the service or HTML.

Storage and migration

Version 1 settings load as version 2 without renaming account keys or browser profile generations. Existing Windows Credential Manager targets continue working. New accounts get random stable IDs. Ordinary settings contain labels, URLs, model IDs and ordering only. Provider keys and the router client key live in Windows Credential Manager. They are never returned in bootstrap data. Forget clears the selected account's credentials and sessions while preserving other accounts.

The listener binds IPv4 loopback only. It rejects browser Origin headers and unexpected Host values. Client authentication is required on both endpoints. Local model URLs accept loopback/private IPs, reject URL credentials and arbitrary paths, and do not follow redirects or system proxies. Remote provider sign-in windows still have no native-command permissions.
